# Keep a problem log

`ideas` · stages: idea · status: candidate · source: author-experience

**Pick:** Log every real problem you hit while working; the unsolved ones are video ideas

**What:** A running list in `Workflow/Ideas.md` → Problem log of problems the user actually hit while testing tools or making videos: what they tried, what failed, and whether they found a fix.

**Why it works:** A real problem arrives with the proof the package and the hook need (recordings, logs, the before and after), and nobody else has exactly the same story.

**How we apply it:** Whenever a session stalls on something the first search doesn't solve, add one dated line with the files that show it. `video-ideas` reads the log before proposing ideas; a solved entry becomes a candidate with its proof already listed.

**Use when / skip when:** Use on channels about tools, workflows or making things. Skip entries that only make sense with private client material.

**Check:** Each idea taken from the log names the recordings or files that prove what happened.
